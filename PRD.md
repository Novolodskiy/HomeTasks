## 1. Обзор продукта

### 1.1 Краткое описание
HomeTasks — мобильное приложение для совместного управления бытовыми задачами семьи. Каждый член семьи видит общий список задач, может добавить новую, взять её на себя, оставить комментарий и отметить выполненной.

### 1.2 Проблема
В обычной семье ежедневно возникают десятки бытовых задач: купить продукты, отвезти ребёнка на тренировку, починить кран, выбрать подарок, отвезти кошку к ветеринару, подобрать одежду на мероприятие. Эти задачи живут в разных местах:
- В голове одного из родителей (теряются)
- В личных приложениях типа Apple Reminders / Google Tasks (не видны другим)
- В мессенджерах (тонут в потоке сообщений)
- На бумажках и в холодильнике (не работает на расстоянии)

Существующие решения (Todoist, TickTick, Cozi) либо слишком сложные (категории, проекты, фильтры), либо локализованы под индивидуальное использование, либо требуют слишком много настроек, чтобы быть полезными для обычной семьи.

### 1.3 Решение
Простое мобильное приложение с одним общим списком задач для семьи. Низкий порог ввода (любой член семьи добавляет задачу за пару секунд), общий контекст (все видят, что происходит), минимум настроек.

### 1.4 Позиционирование
> «Общий список дел для семьи. Просто, как стикеры на холодильнике, но всегда с собой.»

### 1.5 Что НЕ является продуктом
- HomeTasks **не** заменяет персональный таск-менеджер для работы
- HomeTasks **не** является календарём или планировщиком
- HomeTasks **не** содержит проектов, тегов, фильтров, приоритетов
- HomeTasks **не** автоматизирует семейный быт через интеграции с умным домом

## 2. Целевая аудитория

### 2.1 Основной сегмент
Семьи из 2-6 человек:
- Родители 28-50 лет
- 0-3 ребёнка любого возраста
- Оба родителя пользуются смартфоном
- Сценарии быта: покупки, доставки, мелкий ремонт, школа/секции/мероприятия, подарки, рутина (кошки, растения, машина)

### 2.2 Вторичные сегменты (потенциал, не таргет MVP)
- Пары без детей (быт двоих)
- Мульти-поколенные семьи (родители + бабушки/дедушки)
- Соседи по квартире / коливинги
- Семьи с приходящим персоналом (няня, помощница по дому)

### 2.3 Психографика
- Не «гик-продуктивность», а обычные люди
- Не настраивают приложение, ожидают что «работает из коробки»
- Ценят то, что не нужно учиться
- Часто принимают решение о покупке на основе доверия (рекомендации друзей/семьи)

## 3. Цели и метрики успеха

### 3.1 Бизнес-цели
**Этап 1 (Бета на русском, 1-3 месяца после релиза):**
- 50-100 семей в закрытой бете
- 10+ семей с активным использованием более 30 дней (retention)
- Минимум 20 интервью с пользователями для валидации продукта

**Этап 2 (Глобальный paid релиз, 6-12 месяцев):**
- 500-1000 платящих семей по всему миру
- $5-12K MRR (Monthly Recurring Revenue)
- D30 retention > 25% для активных юзеров

### 3.2 Продуктовые метрики (для отслеживания)
| Метрика | Целевое значение |
|---|---|
| Время от установки до создания первой задачи | < 60 секунд |
| Среднее число задач, созданных в семье за неделю | > 10 |
| Доля задач, дошедших до Done | > 60% |
| Доля семей с 2+ активными участниками | > 70% |
| Средняя длина сессии | 30-90 секунд (короткие визиты) |
| Частота открытия приложения | 3-7 раз в день |

## 4. Стратегия запуска

### 4.1 Этап 1 — Закрытая бета на русском
- **Срок реализации:** 2-3 недели разработки
- **Дистрибуция:** TestFlight (iOS) + Internal Testing (Android)
- **Аудитория:** 20-50 семей из круга знакомых
- **Стоимость для пользователя:** Бесплатно
- **Цель этапа:** валидация продукта, сбор обратной связи, отладка стабильности
- **Критерий выхода:** 10+ семей активно используют приложение более 30 дней без критичных багов

### 4.2 Этап 2 — Открытая бета на русском
- **Срок:** через 1-2 месяца после этапа 1
- **Дистрибуция:** App Store + Google Play (free tier)
- **Аудитория:** русскоязычные пользователи через органический трафик (соцсети, отзывы пользователей этапа 1)
- **Стоимость:** Бесплатно
- **Цель:** масштабирование до 500+ семей, отшлифовка UX

### 4.3 Этап 3 — Глобальный платный релиз
- **Срок:** через 4-6 месяцев после этапа 1
- **Дистрибуция:** App Store + Google Play
- **Языки:** Английский (основной), русский (второй)
- **Стоимость:** Подписка $7-12/мес или $59-89/год за семью
- **Цель:** монетизация, выход на $5-12K MRR

## 5. Скоуп MVP (Этап 1 — Бета)

### 5.1 In Scope (входит в первую версию)

#### Аутентификация
- Регистрация и вход через email + пароль
- Восстановление пароля по email
- Хранение профиля: имя, аватар (опционально)

#### Семья
- Создание семьи при первом входе
- Генерация инвайт-ссылки для приглашения членов семьи
- Принятие инвайта по deep-link
- Список членов семьи с возможностью удаления (только для owner)
- Лимит: до 8 членов в одной семье

#### Задачи
- Создание задачи: название (обязательно), описание (опционально), дедлайн (опционально), assignee (опционально)
- Просмотр списка задач семьи
- Открытие карточки задачи
- Изменение полей задачи (любой член семьи может править)
- Удаление задачи (только создатель или owner семьи)

#### Статусы задач
- 4 статуса: **To Do**, **In Progress**, **Done**, **Cancelled**
- Ручное переключение статуса любым членом семьи
- **Авто-правило:** если у задачи в статусе To Do наступает дедлайн (равен сегодня в TZ устройства), статус автоматически меняется на In Progress (тихо, без уведомления)
- Done и Cancelled задачи скрываются из основных списков, доступны во вкладке «Архив»

#### Группировка задач (views)
Списки определяются автоматически по дедлайну, а не вручную:
- **Today** — задачи с дедлайном = сегодня + просроченные (с подсветкой)
- **Soon** — задачи с дедлайном в ближайшие 7 дней
- **Later** — задачи без дедлайна или с дедлайном более 7 дней
- **Archive** — задачи в статусе Done или Cancelled

#### Карточка задачи
- Все поля задачи (название, описание, дедлайн, assignee, статус)
- Список комментариев в хронологическом порядке
- Возможность написать комментарий любому члену семьи
- Список вложений (файлы и фото)

#### Комментарии
- Текстовые комментарии под задачей
- Real-time обновления (все участники видят новый комментарий сразу)
- Без упоминаний (@user)
- Без редактирования и удаления комментариев в первой версии

#### Вложения
- Прикрепление фото (с камеры или из галереи)
- Прикрепление файлов любого типа
- Лимиты Free: до 5 вложений на задачу, до 10 МБ на файл
- Лимиты Paid: до 20 вложений на задачу, до 50 МБ на файл
- В бете лимиты Paid (бесплатно для всех)

#### Голосовой ввод
- Кнопка микрофона на экране создания задачи
- Распознавание речи на устройстве (без отправки на сервер)
- Поддержка русского языка (для бета-этапа)
- Распознанный текст становится названием задачи

#### Share-sheet
- Интеграция с системным share-sheet iOS и Android
- Возможность создать задачу из любого приложения (например, поделиться товаром из Instagram → задача «купить»)
- В задачу попадает заголовок и URL источника

#### Push-уведомления
События, на которые приходят push:
- Тебе назначили задачу
- Дедлайн твоей задачи через 1 час
- Дедлайн твоей задачи сегодня в начале дня
- Новый комментарий в задаче, где ты участник или assignee
- Кто-то отметил Done задачу, в которой ты был assigned

#### Оффлайн-режим
- Read-кеш: открытие приложения без сети показывает последний загруженный список задач
- Optimistic UI: создание/изменение задачи работает без сети, изменения видны мгновенно
- Очередь мутаций: пока сети нет, все изменения копятся локально
- Синхронизация: при появлении сети очередь автоматически отправляется на сервер
- Разрешение конфликтов: last-write-wins по timestamp

#### i18n / локализация
- Бета-релиз: только русский язык
- Архитектурно: все строки UI вынесены в `locales/ru.json` через i18next
- Английский добавляется как `locales/en.json` без изменений в коде

### 5.2 Out of Scope (НЕ в MVP)

Явно исключено из первой версии — не предлагать без отдельного обсуждения:

- Категории задач (покупки, ремонт и т.п.) — только плоский список
- Теги и метки
- Приоритеты (high/medium/low)
- Подзадачи / чек-листы внутри задачи
- Повторяющиеся задачи (recurring)
- Календарный view
- Геолокационные напоминания
- Шаблоны задач
- AI-классификация и AI-подсказки
- Шаринг задач с пользователями вне семьи
- Чат семьи (вне контекста задачи)
- Веб-версия / desktop-приложение
- Интеграции (Google Calendar, Apple Calendar, Alexa, etc.)
- Виджеты на главный экран
- Apple Watch / Wear OS
- Семейные расписания (кто когда что делает)
- Финансовый учёт (расходы, бюджеты)
- Расширенные роли и права (admin / kid / guest)
- Apple Sign-in / Google Sign-in (только email/password в бете)
- Платежи и подписки (бета бесплатна)
- RuStore (только App Store + Google Play)

### 5.3 Будущие версии (после бета-этапа)

Возможные направления развития, в порядке приоритета:

1. **i18n английский** — добавление en.json, локализация App Store
2. **Платежи** — RevenueCat + Apple IAP + Google Billing

4. **Виджет на главный экран** — список Today

6. **Recurring задачи** — частый запрос пользователей
7. **Apple Watch** — быстрое создание голосом

## 6. Пользовательские истории (User Stories)

### 6.1 Онбординг
- **US-1.** Как новый пользователь, я скачиваю приложение, регистрируюсь по email/паролю и попадаю на экран «создать семью или принять инвайт», чтобы быстро начать работу
- **US-2.** Как первый пользователь в семье, я создаю семью с названием и сразу получаю инвайт-ссылку, чтобы поделиться с супругом
- **US-3.** Как приглашённый член семьи, я открываю инвайт-ссылку из мессенджера, приложение открывается на нужном экране, я регистрируюсь и попадаю в общий список семьи
- **US-4.** Как новый пользователь, я не вижу длительный туториал — приложение само понятно по интерфейсу

### 6.2 Создание задач
- **US-5.** Как член семьи, я могу создать задачу одним тапом из главного экрана, ввести название и сразу её сохранить (не указывая дедлайн / assignee)
- **US-6.** Как член семьи, я могу создать задачу голосом, нажав кнопку микрофона
- **US-7.** Как член семьи, увидев товар в Instagram, я могу через системный share-sheet быстро создать задачу с этим контентом
- **US-8.** Как член семьи, я могу указать дедлайн через простой date-picker (сегодня, завтра, конкретная дата)
- **US-9.** Как член семьи, я могу назначить задачу на конкретного члена семьи или оставить общей

### 6.3 Просмотр и работа с задачами
- **US-10.** Как член семьи, я открываю приложение и сразу вижу список Today (задачи на сегодня и просроченные)
- **US-11.** Как член семьи, я могу свайпнуть между Today / Soon / Later / Archive
- **US-12.** Как член семьи, я могу одним тапом отметить задачу выполненной из списка
- **US-13.** Как член семьи, я могу открыть карточку задачи, увидеть детали и комментарии
- **US-14.** Как член семьи, я могу написать комментарий к задаче и другие участники видят его сразу
- **US-15.** Как член семьи, я могу прикрепить фото к задаче (например, фото поломки)

### 6.4 Уведомления
- **US-16.** Как assignee, я получаю push, когда мне назначают задачу
- **US-17.** Как assignee, я получаю push утром в день дедлайна и за час до конца дня
- **US-18.** Как участник задачи, я получаю push о новом комментарии в ней

### 6.5 Управление семьёй
- **US-19.** Как owner семьи, я могу пригласить новых членов через генерацию ссылки
- **US-20.** Как owner семьи, я могу удалить члена из семьи
- **US-21.** Как член семьи, я могу выйти из семьи самостоятельно

### 6.6 Оффлайн
- **US-22.** Как пользователь в магазине без интернета, я могу открыть приложение и увидеть список покупок
- **US-23.** Как пользователь в магазине без интернета, я могу отметить «куплено» и изменения сохранятся локально
- **US-24.** Как пользователь, я не получаю ошибку при создании задачи без сети — она встаёт в очередь

## 7. Функциональные требования

### 7.1 Бизнес-правила

**BR-1 (Авто-переход статуса).** Система каждые N минут (или при открытии приложения) проверяет задачи семьи. Для каждой задачи в статусе `todo`, у которой `deadline` равен текущей дате в TZ устройства, статус меняется на `in_progress`. Уведомление пользователю не отправляется. Расчёт выполняется на клиенте, не на сервере.

**BR-2 (Просроченные задачи).** Задача считается просроченной, если `deadline` < сегодня в TZ устройства, а статус ≠ `done` и ≠ `cancelled`. Просроченные задачи отображаются в списке Today с визуальной подсветкой (красная метка «Overdue»).

**BR-3 (Done не воскресает).** Авто-правило BR-1 не срабатывает на задачи в статусе `done` или `cancelled`. Если задачу выполнили, она навсегда в архиве, даже если меняется дедлайн.

**BR-4 (Видимость задач).** Задача видна только членам семьи, в которой она создана. Юзер, состоящий в нескольких семьях, видит задачи каждой семьи в своём контексте.

**BR-5 (Удаление задач).** Удалить задачу может только её создатель или owner семьи. У всех остальных есть только статусы (включая Cancelled) для скрытия задачи.

**BR-6 (Удаление семьи).** Удалить семью может только owner. При удалении все задачи и комментарии семьи удаляются. Подтверждение действия обязательно.

**BR-7 (Лимиты на размер контента в бете).** В бета-версии все юзеры получают paid-лимиты вложений (50 МБ × 20 файлов на задачу). После выхода на платный релиз free-tier урезается.

**BR-8 (TZ для авто-перехода).** «Сегодня» определяется по TZ устройства того, кто открыл приложение. Это значит, что один и тот же дедлайн может для папы (Москва) уже сработать как «сегодня», а для мамы (Калининград) ещё нет. Это допустимо в MVP.

### 7.2 Нефункциональные требования

**NFR-1 (Производительность).** Открытие списка задач при наличии 100 задач в семье — не более 1 секунды на iPhone 12 / Pixel 6.

**NFR-2 (Стабильность).** Crash-free сессий > 99.5% (отслеживание через Sentry или аналог).

**NFR-3 (Размер приложения).** Размер установленного приложения < 50 МБ.

**NFR-4 (Поддерживаемые версии ОС).** iOS 15+ и Android 9+ (API level 28+).

**NFR-5 (Безопасность).** Все запросы к Supabase идут через RLS-политики. Юзер физически не может получить доступ к данным чужой семьи на уровне БД.

**NFR-6 (Локализация).** Все пользовательские строки UI вынесены в i18next. Не допускается хардкодинг русских строк в JSX-коде.

**NFR-7 (Конфиденциальность).** Голосовое распознавание работает на устройстве. Голос не отправляется на серверы Anthropic/OpenAI/Google в режиме MVP.

## 8. UX-принципы

### 8.1 Принципы дизайна
1. **Низкий порог ввода.** Создание задачи занимает максимум 3 тапа. Голос — один тап.
2. **Минимум полей.** Обязательное только название. Всё остальное опционально.
3. **Не учим пользователя.** Никаких туториалов, тултипов, онбординг-флоу длиннее 1 экрана.
4. **Список — не доска.** Главный экран — простой список задач, не kanban.
5. **Реальное время = эффект «вместе».** Когда мама пишет комментарий, папа видит его без обновления.
6. **Тихие автоматизмы.** Авто-переходы статусов происходят без уведомлений и подсказок. Юзер обнаруживает их естественно.

### 8.2 Детальное описание экранов

Описания собираются итеративно по согласованию с Product Owner. Каждый экран имеет статус: 🟡 не согласован / ✅ согласован.

---

#### 8.2.1 Sign In ✅

**Назначение:** вход существующего пользователя в приложение.

**UI элементы:**
- Логотип / название «HomeTasks» сверху
- Поле «Email»
- Поле «Пароль» с иконкой «глаз» (показать/скрыть пароль)
- Кнопка «Войти»
- Ссылка «Забыли пароль?» под полями
- Внизу — ссылка «Нет аккаунта? Зарегистрироваться»

**Поведение:**

- Apple Sign-in / Google Sign-in (в MVP только email + пароль)

#### 8.2.3 Главный экран ✅

**Назначение:** основной рабочий экран приложения. Показывает все задачи семьи, разбитые по срокам, и членов семьи в верхней части.

**Header (горизонтальный ряд сверху):**
- Аватары членов семьи с именами под ними
- В конце ряда — кнопка «+» для добавления нового члена в семью
- Тап по **своему** аватару → экран **Профиль**
- Тап по **чужому** аватару → экран **Семья**
- Тап по «+» → экран **Добавить члена в семью**

**Список задач (скроллится вниз):**
Четыре секции в фиксированном порядке:

1. **Сегодня** — содержит:
   - Просроченные задачи (дедлайн < сегодня), визуально подсвечены красной меткой
   - Задачи с дедлайном на сегодня
   - Задачи со статусом «Выполняю» (вручную поднятые сюда)
2. **Скоро** — задачи с дедлайном в диапазоне «завтра — +5 дней»
3. **Когда-то** — задачи с дедлайном более 5 дней или без дедлайна
4. **Архив** — выполненные и отменённые задачи (срок хранения 7 дней, после удаляются)

Сортировка внутри секции — по дедлайну от ближайшего. Задачи без дедлайна в секции «Когда-то» — в конце.

**Карточка задачи в списке (одна строка):**
- Название задачи
- Дедлайн (дата + время, если время указано)
- Аватар assignee, если задача назначена на конкретного члена семьи

**Действия с задачей:**
- Тап по строке → открывается карточка задачи
- Свайпы по задачам **не используются** — все действия через карточку

**Внизу — две кнопки:**
- Кнопка «+» (FAB) → открывает экран ручного создания задачи
- Кнопка микрофона (FAB) → push-to-talk голосовое создание задачи через AI

**Голосовое создание задачи (push-to-talk):**

Юзер зажимает кнопку микрофона на главном экране и удерживает её, пока говорит. Отпускает — голос обрабатывается AI и автоматически создаётся задача.

Поведение во время удержания:
- Кнопка микрофона увеличивается и меняет цвет
- Поверх главного экрана появляется overlay с анимированным микрофоном, индикатором уровня звука и распознаваемым текстом в реальном времени
- Подсказка «Свайп влево, чтобы отменить» в нижней части overlay
- Лимит длительности записи — до 2 минут

Отпускание:
- Если палец на кнопке → запись завершается, начинается обработка
- Если палец сдвинут влево от кнопки → запись отменяется, ничего не создаётся
- Слишком короткое нажатие (<0.5 сек) → ничего не происходит

Обработка после отпускания:
- В углу появляется toast «Создаю задачу…»
- Транскрипция голоса в текст — через Whisper API
- Полученный текст передаётся в Claude Haiku 4.5 со структурированным выводом
- AI **не просто транскрибирует**, а анализирует речь и формирует красиво оформленную задачу: чистит «эээ», «короче», «типа», переформулирует, вытаскивает описание и структурные поля
- Через 2-4 секунды задача появляется в списке, toast меняется на «Задача добавлена»

Что AI извлекает из речи:
- **Название** — переформулированное, без слов-паразитов
- **Описание** — если в речи есть пояснения и детали
- **Дедлайн** — дата и время, если упомянуты
- **Assignee** — если упомянут член семьи по имени и его имя совпадает с одним из членов семьи

Дефолты:
- Если AI не распознал дедлайн → задача попадает в секцию **Сегодня**
- Если AI не распознал assignee → задача без назначения

Edge-cases:
- Распознался только шум или тишина → задача не создаётся, toast «Не услышали, попробуйте ещё раз»
- AI распознал странное (ослышался) → задача создаётся как есть, юзер правит в карточке (доверяем AI без preview-шага)
- AI распознал двух одинаковых членов семьи → задача создаётся без assignee

**Чего нет:**
- Названия семьи нигде на экране
- Отдельной иконки «Семья» (заменена рядом аватаров)
- Empty state — если задач нет, показываются только заголовки секций
- Свайп-действий по задачам
- Превью-шага перед сохранением голосовой задачи

#### 8.2.4 Экран создания задачи вручную ✅

**Назначение:** ручное создание задачи без голосового ввода. Открывается по нажатию кнопки «+» (FAB) на главном экране.

**UI элементы (сверху вниз):**

1. **Хедер:** кнопка «×» слева (закрыть), заголовок «Новая задача»
2. **Поле «Название»** — auto-focus, клавиатура открыта сразу, **обязательное**
3. **Поле «Описание»** — многострочное, опционально
4. **Дата выполнения** — опционально:
   - Кнопка-плашка «Добавить дату»
   - При тапе → date-picker (выбор даты и опционально времени)
5. **Назначить** — опционально:
   - Кнопка-плашка «Назначить»
   - При тапе → список членов семьи с аватарами + опция «Никому»
6. **Прикрепить** — опционально:
   - Кнопка «Файл» → системный picker
   - Кнопка «Камера» → системная камера
   - Кнопка «Галерея» → выбор фото из галереи
   - Превью прикреплённого внизу формы
7. **Кнопка «Создать»** внизу экрана

**Обязательность полей:**
| Поле | Обязательность |
|---|---|
| Название | Обязательное |
| Описание | Опциональное |
| Дата | Опциональное |
| Время | Опциональное |
| Assignee | Опциональное |
| Прикрепления | Опциональное |

**Логика кнопки «Создать»:**
- Кнопка отображается в disabled-состоянии, пока поле «Название» пустое
- Тап по disabled-кнопке → визуальная подсветка незаполненного поля «Название» (красная рамка + scroll к нему)
- Кнопка становится active как только в названии есть хотя бы один символ

**Логика секции после создания:**
- Если дедлайн не указан → задача попадает в **Сегодня** (одинаково с голосовым флоу)
- Если дедлайн указан → попадает в соответствующую секцию по дате

**Поведение:**
- При успешном сохранении → возврат на главный экран, новая задача появляется в нужной секции
- При попытке закрыть экран («×») с заполненными полями → диалог подтверждения «Выйти без сохранения?»
- При закрытии без заполнения → возврат без диалога

**Чего нет:**
- Микрофона (голосовое создание — отдельная кнопка на главном экране)
- Тегов, категорий, приоритетов
- Повторений (recurring)

#### 8.2.5 Карточка задачи ✅

**Назначение:** просмотр всех деталей задачи, действия по статусу, общение через комментарии.

**Открывается:** тапом по любой задаче в списке на главном экране.

**Структура карточки (сверху вниз):**

```
[× Назад]
─────────────────
Название (крупным шрифтом)
Описание
Дедлайн (плашка с датой/временем)
Назначено на (плашка с аватаром и именем)
Прикрепления к задаче (грид фото + список файлов)
Создал: [аватар] [имя], [дата создания]
─────────────────
[Выполняю] [Выполнено] [Отменить]
─────────────────
Комментарии:
  [аватар] Анна — 14:30
  «Купил молоко, осталось хлеб»
  [📎 photo.jpg]

  [аватар] Дима — 15:00
  «Ок»
─────────────────
[Поле «Написать комментарий»] [🎙️] [📎] [Отправить]
```

**Поля задачи (верхняя часть):**
- Название (крупно)
- Описание
- Дедлайн (дата + время если указано)
- Assignee (аватар + имя или «Никому»)
- Прикрепления (фото гридом, файлы списком)
- Подпись «Создал [имя], [дата]»

**Кнопки действий (между задачей и комментариями):**
- **«Выполняю»** — переносит задачу в секцию «Сегодня» (текущий дедлайн остаётся)
- **«Выполнено»** — отправляет задачу в секцию «Архив» со статусом Done
- **«Отменить»** — отправляет задачу в секцию «Архив» со статусом Cancelled

Расположение кнопок в середине (а не внизу) сделано чтобы не нужно было скроллить через комментарии до кнопок.

**Лента комментариев:**
- Хронологический порядок (сверху — старые, снизу — новые)
- Каждый комментарий: аватар автора, имя автора, время, текст, прикреплённые файлы
- Realtime обновление через Supabase Realtime — новые комментарии появляются мгновенно
- Long-press на свой комментарий → меню «Редактировать» / «Удалить»
- Чужие комментарии нельзя редактировать или удалять

**Поле ввода комментария (внизу):**
- Текстовое поле с placeholder «Написать комментарий…»
- Кнопка микрофона (🎙️) — push-to-talk голосовой ввод комментария
- Кнопка прикрепления (📎) — добавить файл / фото / снять с камеры
- Кнопка «Отправить»

**Голосовой ввод комментария (push-to-talk):**
- Зажать кнопку микрофона, говорить, отпустить
- Whisper API транскрибирует голос
- Claude Haiku оформляет (чистит «эээ», «короче», переформулирует)
- Готовый текст вставляется в поле ввода
- Юзер может проверить, отредактировать и нажать «Отправить»

**Права (зафиксировано):**

| Действие | Кто может |
|---|---|
| Править поля задачи (название, описание, дедлайн, assignee) | Только создатель |
| Прикреплять файлы к самой задаче | Только создатель |
| Оставлять, редактировать и удалять свои комментарии | Любой член семьи (свои) |
| Жать «Выполняю» / «Выполнено» / «Отменить» | Создатель или assignee |
| Удалять задачу | Никто (нет такой кнопки) |

**Поведение:**
- Изменения полей задачи (для создателя) сохраняются автоматически без отдельной кнопки
- Закрытие через «Назад» возвращает на главный экран
- При нажатии на любое поле, к которому нет прав — нет реакции (поле просто read-only)

**Push-уведомления, инициируемые из карточки:**
- Новый комментарий → push **создателю задачи** и **assignee** (если они не автор комментария)
- Изменение статуса задачи на «Выполнено» → push создателю и assignee

**Чего нет:**
- Кнопки удаления задачи (используется «Отменить»)
- Упоминаний (@user) в комментариях
- Истории изменений задачи
- Read-receipts (кто прочитал комментарий)

#### 8.2.6 Экран «Семья» ✅

**Назначение:** просмотр членов семьи, добавление новых, удаление участников, выход из семьи.

**Открывается:** тапом по чужому аватару в верхнем ряду главного экрана.

**Хедер:**
- Кнопка «Назад» слева
- Заголовок «Семья»

**Содержимое:**

1. **Список членов семьи (вертикальный):**
   - Каждая строка: аватар, имя, username
   - Себя в списке отмечен пометкой «(вы)»
   - Тап по строке — ничего не происходит (декоративный список)
   - У строк других членов справа — иконка «Удалить» (только если текущий юзер является создателем семьи)

2. **Кнопка «Добавить члена»** — переходит на экран **Добавить члена в семью**

3. **Кнопка «Выйти из семьи»** внизу экрана — для всех участников

**Права:**

| Действие | Кто может |
|---|---|
| Удалить другого члена из семьи | Только создатель семьи |

**Чего нет:**

- Тапа по члену семьи (никакого действия)
- Раздела ролей (admin / kid / guest) — все равны
- Возможности передать права создателя другому участнику

**Открытые edge-cases (для системного аналитика):**
- Что происходит с задачами одиночной семьи при принятии инвайта в чужую (удаляются / переносятся / спрашивается у юзера)
- Что происходит с семьёй, когда выходит создатель (права переходят следующему по старшинству / семья удаляется / другое)
- Что происходит с семьёй, когда из неё вышли все участники (удаляется автоматически вместе с архивом задач)

- Кнопка «Назад» слева

   - Placeholder «Введите username»
   - Debounce 300мс между вводом и запросом
   - Поиск нечувствителен к регистру

2. **Результаты поиска:**
   - Список совпадений: аватар + имя + username

   - Если юзер уже в семье → «Уже в семье», кнопка disabled
   - Если уже отправлен инвайт → «Приглашение отправлено», кнопка disabled

   - Текст: «Никого не нашли. Возможно, у этого человека ещё нет аккаунта»

**Поведение приглашённого пользователя:**
- Получает push «[Имя] приглашает вас в семью»
- На главном экране в верхнем ряду аватаров появляется отдельная плашка-инвайт «Приглашение от [Имя]» с двумя кнопками — «Принять» и «Отклонить»
- Тап «Принять» → юзер переходит в новую семью; плашка исчезает
- Тап «Отклонить» → инвайт удаляется; плашка исчезает
- Если юзер не реагирует 7 дней → плашка автоматически исчезает

**Чего нет:**
- Поиска по email и телефону (только username)
- Возможности пригласить нескольких пользователей разом (только по одному)
- Кастомного текста сопровождения к инвайту (стандартный текст для всех)
- Отзыва уже отправленного приглашения

#### 8.2.8 Экран «Профиль» ✅

**Назначение:** просмотр и редактирование собственных данных, настройка push-уведомлений, выход и удаление аккаунта.

**Открывается:** тапом по своему аватару в верхнем ряду главного экрана.

**Хедер:**
- Кнопка «Назад» слева
- Заголовок «Профиль»

**Содержимое (сверху вниз):**

1. **Аватар** (большой по центру)
   - Тап → выбор: «Снять с камеры», «Из галереи», «Удалить»

2. **Имя** — тап → inline редактирование

3. **Username** — серым текстом, read-only (нельзя менять для сохранения целостности инвайтов и поиска)

4. **Email** — серым текстом, рядом маленькая кнопка «Сменить»
   - При тапе на «Сменить» → открывается экран смены email (старый email, новый email, на новый отправляется код подтверждения)

5. **Раздел «Безопасность»:**
   - Кнопка «Сменить пароль» → открывается экран с полями «Старый пароль» и «Новый пароль»

6. **Раздел «Уведомления»** — тогглы push:
   - Назначенная задача
   - Дедлайн сегодня
   - Новый комментарий
   - Задача отмечена «Выполнено»

7. **Раздел «Аккаунт»:**
   - Кнопка «Выйти из аккаунта» — простой logout, возврат на Sign In
   - Кнопка «Удалить аккаунт» — с подтверждением действия

8. **Низ экрана** (мелким серым):
   - Версия приложения
   - Ссылка на политику конфиденциальности

**Поведение при удалении аккаунта:**
- Аккаунт помечается как удалённый (soft-delete)
- Задачи, созданные пользователем, **остаются у семьи** в нетронутом виде
- Комментарии пользователя остаются на местах
- Если пользователь был assignee активной задачи — назначение **остаётся**, но имя отображается как «Удалённый пользователь»
- Если пользователь был создателем семьи — права создателя автоматически переходят следующему по дате присоединения участнику

**Поведение при смене email:**
- Юзер вводит новый email
- На новый email отправляется код подтверждения
- После подтверждения email обновляется в Supabase Auth
- Старый email перестаёт быть привязан к аккаунту

**Поведение при смене пароля:**
- Юзер вводит старый пароль для проверки
- Затем дважды (или один раз) новый пароль
- При успехе — экран закрывается, пользователь остаётся залогинен

**Чего нет:**
- Раздела «Семья» (это отдельный экран, открывается с главного)
- Настроек языка (бета только на русском)
- Настроек темы оформления (используется системная тёмная/светлая)
- Просмотра статистики и активности

#### 8.2.9 Экран «Восстановление пароля» ✅

**Назначение:** запуск процесса сброса пароля по email.

**Открывается:** тапом по ссылке «Забыли пароль?» на экране Sign In.

**Хедер:**
- Кнопка «Назад» слева (возврат на Sign In)
- Заголовок «Восстановление пароля»

**Содержимое:**
- Поясняющий текст сверху: «Введите email — мы пришлём ссылку для сброса пароля»
- Поле «Email» (auto-focus)
- Кнопка «Отправить ссылку»

**Поведение:**
- При тапе «Отправить ссылку» → вызов `supabase.auth.resetPasswordForEmail(email)`
- После отправки → экран-подтверждение «Проверьте почту. Если письма нет — проверьте папку Спам»
- На указанный email приходит письмо с deep-link на сброс
- Тап по deep-link → открывает приложение на экране «Установить новый пароль» (поле «Новый пароль» + кнопка «Сохранить»)
- После сохранения пароля → автоматический вход в аккаунт и переход на главный экран

**Чего нет:**
- Восстановления через SMS или телефон
- Секретных вопросов
- Возможности установить временный пароль

## 10. Архитектурные решения

### 10.1 Multi-platform single codebase
Один Expo-проект, одна кодовая база, две сборки (iOS + Android). Платформенные различия минимизированы.

### 10.2 Local-first lite
Не полный CRDT, но локальный кеш + очередь мутаций. Покрывает 90% оффлайн-сценариев. Возможность позже наслоить полный local-first sync (PowerSync, Replicache) без переписывания.

### 10.3 i18n с первого дня
Все строки в JSON-файлах локалей. Бета-релиз — только русский, но архитектура готова к расширению.

### 10.4 Авто-переход статуса — на клиенте, не на сервере
Расчёт «сегодня» зависит от TZ юзера. Серверная cron-job не знает, в каком TZ конкретный пользователь. Поэтому переход вычисляется на клиенте при загрузке списка задач.

### 10.5 Realtime через Supabase
Используем Supabase Realtime для комментариев. Для задач — по pull-to-refresh + при возвращении в приложение из background.

## 11. Монетизация

### 11.1 Бета-этап
Полностью бесплатно. Все фичи доступны всем пользователям.

### 11.2 После выхода на глобальный платный релиз

**Free план:**
- 1 семья
- До 3 человек в семье
- До 30 активных задач (не считая архив)
- Без вложений (или 5 вложений × 10 МБ)
- Без расширенных видов

**Premium семейный план:**
- Цена: $7-12/мес или $59-89/год (точная цена A/B-тестируется)
- До 8 человек в семье
- Безлимит активных задач
- Вложения 20 × 50 МБ на задачу
- Будущие фичи (виджеты, recurring, шаблоны)

Подписка покупается на одного юзера, активирует premium для всей семьи.

### 11.3 Каналы платежей
- **iOS:** Apple In-App Purchase (комиссия 30% / 15% после года или 15% сразу через Small Business Program)
- **Android:** Google Play Billing (комиссия 30% / 15% после года)
- **Менеджмент:** RevenueCat (бесплатно до $2.5K MTR, потом 1%)

## 12. Риски и открытые вопросы

### 12.1 Технические риски
| Риск | Вероятность | Митигация |
|---|---|---|
| Сложность реализации оффлайн-очереди в срок | Высокая | Возможно сократить скоуп оффлайна до read-only кеша на бету |
| Apple отклоняет приложение при первой подаче | Средняя | Заранее изучить App Store Review Guidelines, иметь готовые ответы |
| Низкое качество распознавания русской речи на Android | Средняя | Фоллбек на текстовый ввод, тест на нескольких устройствах |
| Realtime-комментарии глючат на слабом интернете | Средняя | Локальный кеш комментариев + retry-логика |

### 12.2 Продуктовые риски
| Риск | Вероятность | Митигация |
|---|---|---|
| Бета-юзеры не понимают ценность без расширенных фич (recurring, calendar) | Средняя | Проводить интервью, готовиться к добавлению recurring во второй итерации |
| Семьи не достигают 2+ активных юзеров (один родитель пользуется, другой нет) | Высокая | Упростить инвайт-флоу до максимума, замотивировать первого юзера пригласить второго |
| Конкуренция с уже сложившимся продуктом (Cozi, Apple Reminders Family) | Высокая | Узкий фокус на «нулевое трение ввода» как уникальное предложение |

### 12.3 Бизнес-риски
| Риск | Вероятность | Митигация |
|---|---|---|
| Глобальный paid-релиз не достигает 500 платящих за 12 месяцев | Высокая | Реалистично оценивать unit-экономику, иметь план продлить бета-этап |
| Комиссия Apple/Google съедает маржу | Средняя | Подаваться в Small Business Program (15% комиссия с первого года) |

### 12.4 Открытые вопросы (требуют решения)
- Точная цена подписки (диапазон $7-12/мес — нужен A/B-тест на реальной аудитории)
- Доступность доменов и App Store-имени «HomeTasks» — нужна проверка
- Стратегия роста на глобальном этапе (Product Hunt, ASO, контент-маркетинг)
- Юридическая форма для приёма платежей (ИП в РФ / ООО / зарубежная сущность)

Дизайн (Code Design)

## 14. Приложения

### 14.1 Глоссарий
- **Семья (Family)** — группа из 2-8 пользователей, разделяющая список задач
- **Член семьи (Member)** — пользователь, состоящий в семье
- **Owner семьи** — пользователь, создавший семью или получивший права owner
- **Задача (Task)** — единица работы в общем списке семьи
- **Assignee** — член семьи, на которого назначена задача
- **Дедлайн (Deadline)** — дата (без времени), к которой задача должна быть выполнена
- **MVP** — Minimum Viable Product, первая работоспособная версия для беты
- **TZ** — Time Zone, часовой пояс устройства
