## 0. Терминология окружений (фиксируем для всех документов)

Используются строго эти термины:

| Термин | Что входит |
|---|---|
| **Продовое окружение** (prod) | App Store / Google Play production билд + отдельный Supabase production проект. Реальные пользователи |
| **Тестовое окружение** (stage) | Один Supabase stage проект (общий) + TestFlight (iOS) / Internal Testing (Android) билды |

Внутри тестового окружения:
- **master** — главная git-ветка, последний код для регресса
- **dev-ветки** — feature-ветки в разработке

### Поток разработки

```
Локально (Docker Supabase + Expo Go)
   │ git push
   ▼
Dev-ветка → можно собрать в TestFlight как отдельный билд
   │ git merge → master
   ▼
master → собирается в TestFlight как основной master-билд
   │ регрессы прошли → деплой в прод
   ▼
Продовое окружение (App Store / Google Play)
```

### Параллельные билды в TestFlight

В тестовом окружении на iOS можно одновременно держать несколько билдов с разными Bundle ID:

```
com.hometasks               ← продовый (App Store)
com.hometasks.master        ← master билд в TestFlight (всегда есть)
com.hometasks.voice-input   ← билд из dev-ветки voice-input
com.hometasks.comments-fix  ← билд из dev-ветки comments-fix
```

На телефоне тестера это разные приложения с разными иконками — можно установить все одновременно. Все билды подключены к **одному** stage Supabase (общая БД, общее хранилище).

### Кто что использует

| Окружение | Кто работает |
|---|---|
| Локально | Только разработчик (тяжёлые эксперименты, локальный Docker Supabase) |
| Тестовое (stage) | Разработчик + бета-тестеры (через TestFlight / Internal Testing) |
| Продовое (prod) | Реальные пользователи |

## 1. Общая картина одной фразой

HomeTasks — это **мобильное приложение** на телефонах семьи, которое **синхронизируется с одним облачным сервером** (Supabase). Когда юзер диктует задачу голосом, телефон отправляет голос **двум внешним AI-сервисам** (Whisper для транскрипции, Claude Haiku для оформления), получает обратно красивую задачу и сохраняет её на сервер. Все остальные члены семьи видят эту задачу мгновенно через **realtime-канал** Supabase.

```
   📱 Папа          📱 Мама          📱 Дочь
      │                │                │
      └────────┬───────┴────────┬───────┘
               │                │
        ┌──────▼────────────────▼──────┐
        │          Supabase             │   ← один сервер
        │  • БД (Postgres)              │
        │  • Auth                       │
        │  • Storage (фото/файлы)       │
        │  • Realtime (мгновенные       │
        │    обновления)                │
        └──────┬─────────────────┬──────┘
               │                 │
        ┌──────▼──────┐   ┌──────▼──────────┐
        │ OpenAI      │   │ Anthropic       │
        │ Whisper API │   │ Claude Haiku    │
        │ (голос →    │   │ (текст → задача)│
        │  текст)     │   │                 │
        └─────────────┘   └─────────────────┘
```

## 2. Что находится на телефоне юзера

Это «мозг» приложения, с которым непосредственно общается человек. На телефоне работает Expo (React Native).

### 2.1 Что хранится на телефоне

- **Локальный кеш задач** — последний список задач семьи в SQLite. Открыл приложение без интернета — список уже виден.
- **Очередь несинхронизированных изменений** — если юзер создал задачу без сети, она лежит в локальной очереди и ждёт момента, когда появится интернет.
- **Сессия авторизации** — токен Supabase, чтобы каждый раз не вводить пароль.
- **Настройки и кеш переводов** (i18n) — чтобы не качать каждый раз.
- **Push-токен** — уникальный идентификатор телефона для отправки уведомлений.

### 2.2 Что приложение делает

- Показывает экраны и списки.
- Принимает ввод от юзера (текст, голос, фото).
- Шлёт запросы на Supabase (получить задачи, создать, обновить).
- Шлёт голос на Whisper и Claude — но **только при голосовом создании**.
- Получает push от Supabase (когда что-то происходит — назначили задачу, новый комментарий).
- Подключается к Realtime-каналу Supabase, чтобы видеть изменения от других членов семьи мгновенно.

### 2.3 Что приложение НЕ делает

- Не хранит чужие данные (только свою семью).
- Не общается напрямую с другими телефонами (вся синхронизация через сервер).
- Не делает тяжёлой логики (вся бизнес-логика и проверки прав — на сервере).

## 3. Что находится на сервере (Supabase)

Supabase — это «коробка», которая включает в себя всё необходимое для backend-а. Не нужно поднимать свои серверы, не нужно настраивать БД, не нужно писать API. Всё уже готово.

### 3.1 База данных (PostgreSQL)

Здесь хранятся все данные приложения:

- **profiles** — профили пользователей (имя, username, аватар)
- **families** — семьи (контейнеры для задач)
- **family_members** — кто в какой семье состоит, с какой ролью (создатель / участник)
- **family_invites** — отправленные приглашения
- **tasks** — все задачи всех семей
- **task_comments** — комментарии к задачам
- **task_attachments** — вложения к задачам
- **comment_attachments** — вложения к комментариям
- **push_tokens** — токены устройств для отправки push
- **subscriptions** — статусы подписок (для будущей платной версии)

### 3.2 Auth (аутентификация)

Supabase сам обрабатывает регистрацию, вход, восстановление пароля, отправку email с кодами. Мы просто вызываем функции `signUp`, `signIn`, `resetPassword` — всё остальное он делает сам.

### 3.3 Storage (файлы)

Сюда заливаются фото и файлы из задач и комментариев. Каждое вложение получает свой URL, по которому его потом можно скачать. Storage сам сжимает фото, генерирует thumbnail, обрабатывает типы файлов.

### 3.4 Realtime (реалтайм-обновления)

Когда мама создала задачу, как папа узнаёт об этом мгновенно? Через Realtime-канал. Это технология «WebSocket» — постоянное соединение между телефоном и сервером. Сервер сам сообщает всем подписанным телефонам, что в БД произошло изменение.

В нашем приложении Realtime используется для:
- Новых задач в семье
- Обновлений статуса задач (Выполнено / Отменить)
- Новых комментариев
- Изменений профилей семьи (например, новый член присоединился)

### 3.5 Row Level Security (RLS)

Это «замки» на таблицах. RLS — это правила вида: «юзер может видеть только те задачи, которые принадлежат семье, в которой он состоит». Эти правила прописываются один раз в БД, и Supabase **физически** не отдаёт данные тому, у кого нет прав.

Это критично для безопасности: даже если юзер взломает приложение и попробует сделать запрос «дай мне все задачи всех семей», БД откажет.

### 3.6 Edge Functions (серверные функции)

Это «маленькие функции», которые запускаются на сервере, когда нужна особая логика. Например:
- Подтвердить и обработать платёж от RevenueCat (на будущее)
- Очистить просроченные приглашения раз в день
- Удалить из архива задачи старше 7 дней
- Отправить push при создании комментария

### 3.7 Cron-задачи (расписание)

Supabase позволяет запускать функции по расписанию. Используем для:
- Удаление просроченных инвайтов раз в час
- Удаление архивных задач старше 7 дней раз в день
- Отправка push-уведомлений о дедлайнах в начале дня

## 4. Внешние AI-сервисы

Это сторонние сервисы, к которым обращается **наш Edge Function на бэкенде** (не телефон напрямую). Это критично для безопасности — API-ключи Whisper и Claude хранятся в переменных окружения Supabase, не в коде мобильного приложения. Если зашить ключи в приложение, любой может их извлечь из бинарника и тратить деньги с вашего счёта.

### 4.1 OpenAI Whisper API

**Что делает:** превращает голос в текст. Принимает аудио (записанный голос), возвращает текстовую транскрипцию.

**Когда используется:** каждый раз, когда юзер зажимает кнопку микрофона на главном экране или в комментариях.

**Стоимость:** $0.006 за минуту аудио.

**Альтернатива:** есть встроенное в телефон распознавание (`expo-speech-recognition`). Оно бесплатно, но качество хуже, особенно на русском. На бета-этапе можно использовать встроенное, на платной версии — Whisper.

### 4.2 Anthropic Claude Haiku 4.5

**Что делает:** превращает «сырой» текст («эээ типа купить молоко короче на завтра») в **структурированную задачу** с полями: название, описание, дедлайн, assignee.

**Когда используется:** после Whisper, когда есть транскрипция голоса.

**Стоимость:** ~$0.0008 за задачу (Haiku очень дешёвая).

**Что передаётся в промпт:**
- Текст транскрипции
- Текущая дата и время
- Список членов семьи (имена и usernames) — чтобы AI понял, кого имеют в виду

**Что возвращается:** JSON с полями задачи. Если AI не уверен в каком-то поле — оставляет его пустым.

## 5. Как происходят основные сценарии

### 5.1 Сценарий: «Папа создаёт задачу голосом»

**ВАЖНО:** AI-сервисы вызываются **через Edge Function на бэкенде**, не напрямую с телефона. Это сделано для безопасности — API-ключи Whisper и Claude хранятся на сервере, не в коде мобильного приложения.

1. Папа на главном экране зажимает кнопку микрофона
2. Телефон записывает аудио в локальный буфер
3. Папа отпускает кнопку
4. Телефон отправляет аудио в **Edge Function `process-voice`** на Supabase
5. Edge Function вызывает OpenAI Whisper API (с серверным OPENAI_API_KEY) → получает текст «купить молоко завтра вечером и сказать ане»
6. Edge Function вызывает Anthropic Claude Haiku (с серверным ANTHROPIC_API_KEY), передавая текст + список членов семьи + текущую дату
7. Claude возвращает JSON: `{ title: "Купить молоко", deadline: "2026-05-06T19:00", assignee_username: "anya" }`
8. Edge Function возвращает JSON на телефон
9. Телефон делает POST в Supabase: «создать задачу с этими полями»
10. Supabase сохраняет задачу в БД и возвращает её ID
11. Supabase Realtime рассылает «новая задача!» всем телефонам семьи
12. На телефонах мамы и Ани в списке появляется новая задача
13. Ане приходит push «Папа назначил тебе задачу»

**Сколько занимает:** 2-4 секунды от отпускания кнопки до появления задачи в списке.

**Где лежит код:**
- Frontend (запись звука, отправка): `src/features/voice/`
- Backend (Whisper + Claude + парсинг): `supabase/functions/process-voice/`

### 5.2 Сценарий: «Мама пишет комментарий»

1. Мама открывает карточку задачи «Купить молоко»
2. Телефон делает запрос в Supabase: «дай комментарии этой задачи»
3. Телефон **подписывается** на Realtime-канал этой задачи
4. Мама пишет «Купи 2 литра, не 1»
5. Телефон отправляет POST: «создать комментарий»
6. Supabase сохраняет в БД
7. Realtime-канал рассылает обновление всем подписанным
8. На телефоне Папы и Ани комментарий появляется мгновенно
9. Папе и Ане приходит push «Новый комментарий в задаче»

### 5.3 Сценарий: «Аня прикрепляет фото»

1. Аня в карточке задачи нажимает «Прикрепить» → «Камера»
2. Открывается системная камера, Аня снимает фото
3. Телефон сжимает фото (до ~1 МБ)
4. Телефон загружает файл напрямую в Supabase Storage (минуя нашу БД)
5. Storage возвращает URL файла
6. Телефон делает POST в БД: «добавить attachment с этим URL к этой задаче»
7. Realtime сообщает всем участникам семьи об обновлении

### 5.4 Сценарий: «Дима без интернета в магазине»

1. Дима открывает приложение в магазине без сети
2. Приложение читает задачи из локального SQLite-кеша
3. Дима тапает по задаче «Купить хлеб», нажимает «Выполнено»
4. Изменение сохраняется в локальной очереди мутаций
5. На UI задача мгновенно перемещается в Архив (optimistic UI)
6. Дима выходит из магазина, появляется сеть
7. Очередь мутаций автоматически отправляется в Supabase
8. Все остальные члены семьи видят изменение через Realtime

### 5.5 Сценарий: «Папа добавляет Аню в семью»

1. Папа в списке аватаров на главном тапает «+»
2. Открывается экран Добавить члена в семью
3. Папа вводит «anya2018» в поле поиска
4. Телефон делает GET в Supabase: «найди профили с username похожим на anya2018»
5. Supabase возвращает список совпадений
6. Папа жмёт «Пригласить» рядом с Аниным профилем
7. Телефон делает POST: «создать family_invite»
8. Сервер создаёт инвайт со сроком 7 дней
9. Edge Function отправляет push на устройство Ани
10. На главном экране Ани появляется плашка «Папа приглашает вас в семью»

## 6. Масштаб и нагрузка

### 6.1 Прогноз количества пользователей

| Этап | Регистраций | DAU (активных в день) |
|---|---|---|
| Закрытая бета | 50-100 | 30-50 |
| Открытая бета на русском | 500-2000 | 300-1000 |
| Глобальный платный релиз | 10-50 тыс | 5-20 тыс |

### 6.2 Прогноз нагрузки на пике

Возьмём реалистичный сценарий: **глобальный релиз**, 20 000 DAU.

- Каждый юзер открывает приложение **5-10 раз в день**
- Каждое открытие делает **10-30 запросов** (получить задачи, создать новую и т.п.)
- Итого: 1-6 миллионов запросов в день
- В пике (вечером): ~200-500 одновременно активных юзеров

**Это спокойно держит Supabase Pro tier ($25/мес).** Базы PostgreSQL такого размера держат миллионы запросов в день без проблем.

### 6.3 Прогноз использования голосовых функций

Из 20 000 DAU:
- ~30% активно используют голос (6000 юзеров)
- В среднем 5 голосовых задач в день на юзера
- Итого: 30 000 голосовых задач в день
- Средняя длина записи: 15 секунд

**Стоимость в день:**
- Whisper: 30 000 × 15 сек × $0.006/мин = $45/день = $1350/мес
- Claude Haiku: 30 000 × $0.0008 = $24/день = $720/мес
- **Итого AI-расходы: ~$2000/мес**

При 1000 платящих семей × $9/мес = $9000 MRR — AI стоит ~22% выручки. Это многовато. Можно:
- Использовать встроенное распознавание на бета-этапе (бесплатно)
- Кешировать частые промпты Claude
- Использовать ещё более дешёвый Haiku для простых задач

### 6.4 Прогноз хранилища

| Тип | На юзера | Всего на 20 000 DAU |
|---|---|---|
| Задачи (текст) | ~100 КБ | 2 ГБ |
| Комментарии | ~50 КБ | 1 ГБ |
| Профили + аватары | ~100 КБ | 2 ГБ |
| Вложения (фото/файлы) | ~50-200 МБ | 1-4 ТБ |

**Хранилище:** Supabase Pro даёт 100 ГБ. Всё, что свыше — $0.021/ГБ.

При 4 ТБ вложений = 4000 ГБ × $0.021 = $84/мес доплаты. Терпимо.

Можно ввести лимиты:
- Free: 100 МБ на семью
- Paid: 5 ГБ на семью

### 6.5 Прогноз стоимости инфраструктуры

| Сервис | Месячная стоимость на 1000 DAU | На 20 000 DAU |
|---|---|---|
| Supabase Pro | $25 (фикс) | $25-100 (с большим storage) |
| Whisper API | $50-100 | $1000-1500 |
| Claude Haiku | $20-40 | $500-800 |
| RevenueCat | бесплатно (до $2.5K MTR) | $50-100 (1% от выручки) |
| Expo EAS Build | $0-30 | $30 |
| Sentry (мониторинг) | бесплатно | $0-30 |
| **Итого** | **$100-200/мес** | **$1700-2600/мес** |

При выручке $9K/мес (1000 платящих × $9) = маржа 75-80%. Здоровая экономика.

## 7. Что где хранится

| Данные | Где хранятся | Зачем |
|---|---|---|
| Профили юзеров | Supabase Postgres | Источник правды |
| Задачи | Supabase Postgres | Источник правды |
| Комментарии | Supabase Postgres | Источник правды |
| Файлы и фото | Supabase Storage | Бинарные данные |
| Локальный кеш задач | SQLite на телефоне | Оффлайн-доступ |
| Очередь оффлайн-изменений | SQLite на телефоне | Сохранить изменения без сети |
| Push-токены | Supabase Postgres + Expo Push Service | Отправка уведомлений |
| Sessions / JWT-токены | AsyncStorage на телефоне | Авторизация без повторного входа |
| Аудио голоса | Нигде не хранится | Уходит в Whisper и забывается |

## 8. Безопасность

### 8.1 Кто что видит

- Юзер видит только свой профиль и профили членов своих семей
- Юзер видит только задачи семей, в которых состоит
- Юзер видит только комментарии к этим задачам
- Юзер видит только файлы, прикреплённые к этим задачам и комментариям

Всё это обеспечивается **Row Level Security** (RLS) на уровне БД. Не на уровне приложения. Это критично — даже если приложение взломают, БД не отдаст лишние данные.

### 8.2 Передача данных

- Все запросы идут по **HTTPS** (TLS 1.3)
- Авторизация через **JWT-токены**, которые Supabase валидирует на каждом запросе
- Аудио голоса передаётся в Whisper по HTTPS, OpenAI обещает не использовать его для обучения

### 8.3 Хранение паролей

Supabase Auth хранит пароли в виде **bcrypt-хэшей**. Мы никогда не видим оригинальный пароль. При входе юзер вводит пароль, Supabase хеширует и сравнивает.

### 8.4 Email-верификация

В MVP отключена для простоты. Можно включить позже одной настройкой.

### 8.5 Конфиденциальность голоса

Голос:
- Записывается локально на телефон
- Передаётся в Whisper API (OpenAI) для транскрипции
- **Не хранится** ни у нас, ни у OpenAI
- Текстовая транскрипция передаётся в Claude Haiku
- Готовая задача сохраняется в нашу БД

## 10. Что важно понимать про эту архитектуру

**Простота.** Вся «серверная сторона» — это один Supabase. Мы не пишем свой backend, не поднимаем свои сервера, не настраиваем масштабирование. Supabase делает это сам.

**Безопасность через БД.** Все правила доступа («кто что видит») прописаны в БД через RLS. Это значит, что даже фронт-агент не может случайно открыть лишние данные — БД просто не отдаст.

**Realtime — главная фишка.** Когда мама пишет комментарий, папа видит его без обновления. Это не делается через polling (постоянно дёргать сервер) — это делается через постоянное WebSocket-соединение с Realtime-сервером.

**AI — внешний сервис.** Мы не запускаем свои AI-модели. Мы платим OpenAI и Anthropic за каждый вызов. Это значит — нужно следить за стоимостью, оптимизировать промпты, кешировать где можно.

**Оффлайн — важно для семьи.** Большинство юзеров будут пользоваться приложением в магазине, в подвале, в метро. Архитектура изначально учитывает оффлайн-режим: всё работает без сети, синхронизируется когда сеть появится.

**Один код для двух платформ.** Expo даёт нам iOS и Android из одной кодбазы. Один разработчик пишет — два приложения работают.
